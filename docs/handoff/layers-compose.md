## 0. 한 문장

> **작업은 층으로 나눠서 하고, 런타임에는 합친 파일 하나만 들어간다.**
> 대사 층은 ked-story-director가, 연출 층은 ked-story-tools가 쓴다. 둘은 줄 ID로만 만나고, 합치기는 런타임 밖(툴)에서 한다.

## 1. 왜 — 지금의 문제

조사한 사실(2026-11-27):

- **디렉터는 대사 Yarn을 덮어쓴다.** `ExportDelivery`는 보낼 곳의 파일이 `exported/`와 바이트가 다르면 통째로 다시 쓴다. 합치지 않는다.
- **그래서 디렉터는 대사 Yarn을 게임 폴더로 보내지 않게 막아 두었다**(`runtime-contract.md` §5.5 — 연출 든 Yarn과 노드 이름이 겹친다). 진행 JSON만 저장할 때마다 게임 폴더로 간다.
- **연출을 붙이는 순간 대사가 끊긴다.** 은설 원고(`ked-vn-workspace/stories/eunseol`)는 `exported/`를 스토리 폴더로 손으로 한 번 옮긴 뒤 연출을 붙였다. 그 뒤 디렉터에서 대사를 고쳐도 게임에 들어가지 않는다. 대사 Yarn을 같은 폴더로 보내게 하면 다음 저장 때 연출이 지워진다.
- **이 툴은 대사 줄을 건드리지 않는다**(`LineEditor` — 조작 여섯 모두 커맨드 묶음만 쓴다). 디렉터의 새 대사를 받아들이는 길이 없다.

은설 원고에서 확인한 것: 연출 든 게임 yarn과 디렉터의 `exported/yarn`은 진행 JSON 3개가 같고, 11개 장면 모두 대사 줄 수와 줄 ID가 같다. 다른 것은 연출뿐이다. 대사 줄 안에도 연출 쪽 것이 붙어 있다 — `[beat=in/]` · `#auto=2.0s`.

| L5 | **글이 바뀐 줄의 말 도중 박자 표시는 줄 끝으로 옮기고 표시한다.** 자리는 사람이 다시 놓는다. 글이 바뀌지 않은 줄은 건드리지 않는다 |

## 3. 산출물과 참조 관계

```
stories/<이야기>/
  <이야기>.vnproject.json · story/*.vnstory.json   ← 디렉터 원고 (디렉터만)
  exported/<챕터>.progression.json                 ← 진행 JSON (저장할 때 게임 폴더로 — 지금처럼)
  exported/yarn/<챕터>_<장면>.yarn                 ← 대사 층 (디렉터가 굽는다 — 읽기만)
  staging/<챕터>_<장면>.yarn                       ← 연출 층 (이 툴이 고친다) — 자리는 제안(§9-1)
                    │
                    ▼ 합치기 (대사 층 + 연출 층, 줄 ID로)
runtime/Assets/Dialogue/Story/<이야기>/
  <챕터>.progression.json                          ← 디렉터가 복사
  <챕터>_<장면>.yarn                               ← 게임 yarn (결과물 — 아무도 손으로 고치지 않는다)
  *.motions.json                                   ← 모션 파일 (§9-4)
```

| 산출물 | 쓰는 쪽 | 읽는 쪽 | 용도 |
|---|---|---|---|
| `*.vnproject.json` · `story/*.vnstory.json` | 디렉터 | 디렉터 | 챕터 · 에피소드 · 줄(줄 ID · 화자 · 글) · 지운 줄(`retired`) |
| `exported/*.progression.json` | 디렉터 | 런타임 · 이 툴 | 에피소드의 차례 · 선택지 · 조건, 에피소드가 어느 장면 · 노드인지 |
| `exported/yarn/*.yarn` (대사 층) | 디렉터 | 합치기 · 이 툴 | 대사의 정본 |
| `staging/*.yarn` (연출 층) | 이 툴 | 합치기 · 이 툴 | 줄마다의 연출 · 박자 표시 · 연출 태그, 연출을 붙일 때의 대사(기준) |
| 게임 yarn | 합치기 | 런타임 | 재생할 완성본 |

### 호환의 열쇠 넷

| 열쇠 | 원고 | 진행 JSON | yarn (세 층 모두) |
|---|---|---|---|
| 챕터 ID | `chapters[].chapterId` | `ChapterId` · 파일 이름 | 파일 이름의 앞 |
| 장면 ID | `episodes[].sceneId` | `Nodes[].SceneId` | 파일 이름의 뒤 · 머리의 `// 장면: 이름 (id)` |
| 에피소드 ID | `episodes[].episodeId` = vnstory 노드의 `name` | `EpisodeId` = `DialogueEntryId` | 노드의 `title:` |
| 줄 ID | vnstory의 `lines[].id` | — | 대사 줄 끝의 `#line:` |

디렉터는 `DialogueEntryId`와 노드 이름을 같은 함수로 만든다(`ChapterYarnExporter`). 런타임은 `StartEpisodeId` → `DialogueEntryId` → yarn 노드로 찾아 튼다 — 그 노드가 합친 것인지 모른다.

## 4. 연출 층의 꼴

꼴을 보이려고 지어낸 대본이다.

대사 층 `exported/yarn/ch01_scene01.yarn`:

```
// 장면: 작업실 (scene01)

// 에피소드: 첫 출근
title: ch01_scene01_ep01
---
가람: 오늘부터 여기서 일하게 됐어요. #line:ln_aaaa0001
가람: 잘 부탁드립니다, 정말로요. #line:ln_aaaa0002
===
```

연출 층 `staging/ch01_scene01.yarn`:

```
// 장면: 작업실 (scene01)

// 에피소드: 첫 출근
title: ch01_scene01_ep01
---
// 장면 머리 — 작업실, 한 사람
<<at in bg_spawn bg_main studio_day stage00 far>>
<<at in slot s1>>
<<at in cast s1 garam a 02>>
<<at in fade_in s1 0.57s>> // card:E01
<<gap in 0.4s>>
가람: [beat=in/]오늘부터 여기서 일하게 됐어요. #auto=2.0s #line:ln_aaaa0001

<<at start face s1 05>>
<<at a motion s1 nod>>
가람: 잘 부탁드립니다, [beat=a/]정말로요. #line:ln_aaaa0002
===
```

아무것도 바뀌지 않았으면 게임 yarn은 연출 층과 한 글자도 다르지 않다.

### 연출 층의 줄마다 주인

| 연출 층의 줄 | 주인 | 합칠 때 |
|---|---|---|
| `// 장면:` · 메모 · `// 에피소드:` · `title:` · `---` · `===` · `<<if>>` · `<<else>>` · `<<endif>>` | 디렉터 | 대사 층에서 가져온다(연출 층의 사본은 쓰지 않는다) |
| 대사 줄의 화자 · 글 | 디렉터 | 대사 층에서 가져온다 |
| 대사 줄의 `#line:` | 열쇠 | 두 층을 맞춘다 |
| 대사 줄의 `[beat=…/]` · `#line:` 밖의 태그(`#auto` …) | 연출 | 연출 층에서 가져와 새 글에 다시 얹는다 |
| 대사 줄 앞의 `<<at>>` · `<<gap>>` · 바로 실행하는 명령 · 그 사이의 주석 · 빈 줄 | 연출 | 연출 층에서 가져온다(다음 대사 줄에 딸린다) |
| `===` 바로 앞의 꼬리 명령 | 연출 | 연출 층에서 가져온다(그 노드에 딸린다) |

### 연출 층에 대사를 남기는 까닭

1. 박자 표시가 글 안에 있다 — 자리를 적으려면 글이 있어야 한다.
2. **그 글이 기준(BASE)이다** — "이 연출을 붙일 때의 글". 대사 층과 견주면 작가가 고쳤는지가 나온다. 표시를 따로 적지 않는다.

> **연출 층은 마지막으로 연출가가 확인한 게임 yarn이다.** 평소에는 둘이 같고, 작가가 고쳤는데 연출가가 아직 안 본 줄에서만 갈린다. 그 목록이 연출가의 할 일이다.

## 5. 합치기의 규칙 (제안 — 확정은 §9)

뼈대(파일 · 노드 · 줄의 차례 · 대사 글)는 대사 층을 따르고, 줄에 붙을 연출은 연출 층에서 줄 ID로 찾는다.

| 대사 층 ↔ 연출 층 | 뜻 | 게임 yarn | 연출 층 |
|---|---|---|---|
| 글 · 화자가 같다 | 아무도 안 고쳤다 | 연출 층의 대사 줄을 바이트 그대로 | 그대로 |
| 글이나 화자가 다르다 | 작가가 고쳤다 | 새 글 + 연출 태그 + 말 도중 박자는 줄 끝 | 옛 글을 남긴다(기준) → "다시 볼 것" |
| 연출 층에 없는 줄 ID | 새 줄 | 연출 없이 그 자리에 | 연출 없이 끼운다(§9-2 (가)) → "연출 없음" |
| 대사 층에 없는 줄 ID | 지운 줄 | 뺀다 | 연출을 보관소로(§9-3) |
| 줄이 다른 노드 · 장면으로 갔다 | 옮겼다 | 연출이 줄을 따라간다 | 새 자리로 |

- 연출가가 "다시 볼 것"을 확인하면 연출 층의 대사를 새 글로 갈아 적는다 — 둘이 같아져 표시가 사라진다(gettext의 `fuzzy`를 지우는 것과 같다).
- 끝나면 줄 읽기로 다시 읽어 문제가 하나라도 늘면 쓰지 않는다(`LineEditor`의 규칙 ②와 같다).
- 줄 ID가 두 파일에 겹치면 거절한다.

**시험의 기준 — 왕복:** 대사 층이 연출 층의 대사와 같으면 `합치기(대사 층, 연출 층) == 연출 층`, 바이트 하나 다르지 않다. 몇 번을 돌려도 같다.

### 게임 yarn을 손으로 고쳤을 때 (§9-6)

연출 층의 대사가 기준이니 3-way로 가릴 수 있다.

| 대사 층 = 기준? | 게임 yarn = 마지막 합친 결과? | 뜻 | 합치기 |
|---|---|---|---|
| 같다 | 같다 | 아무도 안 고쳤다 | 그대로 |
| 다르다 | 같다 | 작가가 고쳤다 | 들인다 |
| — | 다르다 | 누가 게임 yarn을 손으로 고쳤다 | 멈추고 알린다 — 대사는 디렉터에서, 연출은 이 툴에서 고친다 |

## 6. 옛 레인 구조에서 배운 것

런타임에 이미 한 번 층을 나눈 적이 있다(2026-06 ~ 08). 마지막 커밋은 `ba267d270`(2026-08-12) — 소유자의 로컬 브랜치 `test/USD`로 보러 갔다(push하지 않음).

| 층 | 파일 | 무엇 |
|---|---|---|
| Story | `@Dialogue/StoryLane/Story_*.yarn` | 대사 + `<<pres_start Pres_…>>` |
| Pres | `@Dialogue/PresLane/Pres_*.yarn` | 대사를 한 벌 베끼고 그 사이에 명령 |
| Beat | `@Dialogue/BeatLane/Beat_*.yarn` | 다시 쓰는 연출 묶음 — 지금의 카드 자리 |

- **줄 수로 맞물렸다.** 두 번째 DialogueRunner가 연출 층을 돌리고, 대사 줄 하나에 연출 줄 하나를 넘겼다(`SyncGatePlanBuilder`). 손잡이는 `pres_hold N` · `pres_advance N` · `#main_free` · `[advance/]`. 되감기 · 불러오기는 그 수만큼 다시 넘겨 맞췄다(`SeekResync`).
- **재생 중에 합쳤다** — 되감기가 느려지고 코드가 어려워졌다(`../PLAN.md` §1.4).
- 걷은 커밋 `a220a5a8d`(2026-08-16)의 이유: 외부 툴로 하나의 파일로 완성해 건네니 유니티 안에서 테이블을 나눌 필요가 없다. **버린 것은 층이 아니라 런타임이 합치는 일이었다** — L1이 그 연장이다.
- 견줄 예가 있다: `Story_blank_ch01_ep00` · `Pres_blank_ch01_ep00`(은설 첫 장 — 대사 194줄씩, 연출 파일 머리에 "대사 텍스트는 원본에서 한 글자도 수정하지 않았습니다").

| | 옛 레인 | 이번 |
|---|---|---|
| 맞물림 | 줄 수 | 줄 ID |
| 합치는 때 | 재생 중 | 저장할 때 툴에서 |
| 런타임이 받는 것 | 파일 둘 이상 | yarn 하나(지금 그대로) |
| 연출 층의 대사 | 베낀 것 — 바뀌면 어긋난다 | 기준 — 바뀌면 "다시 볼 것" |

## 7. 참고한 사례

| 사례 | 가져올 것 |
|---|---|
| gettext `msgmerge` | 원문이 같으면 유지 · 바뀌면 `fuzzy` · 사라지면 `#~` 폐기로 보관. 퍼지 항목에 옛 원문(`#|`)을 같이 보인다 — "다시 볼 것" 옆에 옛 대사를 보인다 |
| Yarn Spinner의 `lock` | 줄 ID(같은 줄인가)와 글의 해시(같은 내용인가)를 따로 든다 — 여기서는 연출 층의 대사가 그 자리다 |
| Ren'Py 번역 식별자 | 열쇠를 내용에서 만들면 글을 고칠 때 끊긴다 — 디렉터가 줄 ID를 발급하고 `retired`로 지키는 것이 맞다 |
| 마야 레퍼런스 편집 | 대상이 사라진 편집을 버리지 않고 "실패한 편집"으로 들고, `changeEditTarget`으로 다시 겨눈다 — 보관소에 "이 줄로 옮기기"가 있어야 한다 |
| USD 레이어 | 부서마다 층, 강한 층이 덮어쓴다, 지우지 않고 끈다. 넘길 때는 하나로 합친 판 |
| 3-way 병합 | BASE가 있어야 누가 바꿨는지 안다 — 연출 층의 대사가 BASE다(§5) |

## 8. 이 저장소에서 바뀌는 결정 (확정은 다음 세션)

| 지금 | 바뀔 방향 |
|---|---|
| D1 — 검토에 넘긴 뒤에는 yarn이 정본이다 | 연출 층이 정본이고 게임 yarn은 합친 결과물이다 |
| §1.4 — 줄 상자를 툴의 파일로 따로 두지 않는다 | 연출 층은 따로 두지만 꼴은 yarn 그대로다 — 정본이 둘이 되지 않는다(대사는 디렉터, 연출은 이 툴) |
| P4 — 앵커를 새로 만들거나 옮기지 않는다 | 박자 표시를 놓는 조작이 하나 더 생긴다(L5) — 글은 그대로, 표지만 움직인다 |
| 관습 — yarn을 쓰는 길은 `LineEditor` 하나 · 고친 줄의 커맨드 묶음만 다시 쓴다 | 연출 층을 쓰는 길은 `LineEditor`, 게임 yarn을 쓰는 길은 합치기. 합치기는 연출 쪽 글을 바이트 그대로 옮긴다 |
| §10 — 대사 글 · 화자 · 분기를 고치기는 디렉터의 일 | 그대로다. 합치기는 대사를 고치지 않고 디렉터의 것을 들인다 |

## 9. 다음 세션에서 정할 것

1. **연출 층의 자리.** 제안: 작업공간의 이야기 폴더 `stories/<이야기>/staging/` — 원고 · 대사 층 · 연출 층이 한 폴더에 모인다. Yarn 프로젝트(`Assets/Dialogue/**/*.yarn`) 밖이어야 한다 — 안에 두면 노드 이름이 겹친다. 공개 런타임의 예제는 어디에 둘지도 정한다.
2. **새 줄 · 지운 줄을 연출 층에 언제 반영하나.** (가) 합치기가 연출 층의 뼈대도 대사 층에 맞춘다 — 이 툴은 늘 파일 하나만 연다(권함). (나) 합치기는 게임 yarn만 쓰고 연출 층은 연출가가 손댈 때만 바뀐다 — 이 툴이 두 파일을 함께 펼쳐야 한다.
3. **보관소의 자리와 꼴.** 제안: 장면마다 `staging/<챕터>_<장면>.retired.yarn` — 같은 꼴이라 이 툴로 열어 "이 줄로 옮기기"를 할 수 있다. 디렉터의 `retired`(지운 줄도 ID와 마지막 글이 남는다)로 되살린 줄을 알아볼지도 정한다.
4. **모션 파일의 자리.** 이 툴은 고치는 대본 곁에 그 편의 `<대본 이름>.motions.json`을 둔다. 연출 층이 `staging/`으로 가면 런타임은 그것을 게임 폴더에서 읽어야 한다. 제안: 합치기가 같이 복사한다(원본은 층에, 결과는 게임 폴더에).
5. **합치기를 누가 부르나.** 이 툴이 고칠 때마다 · 디렉터가 저장할 때 · 손으로(`st`). 셋 다 같은 함수를 부르면 되니 함수부터 짓고 정해도 된다.
6. **게임 yarn을 손으로 고친 것을 만나면** 멈출지 · 경고하고 덮을지(§5).
7. **화면의 표시** — "다시 볼 것"(옛 글과 새 글을 나란히) · "연출 없음" · "박자 다시 놓을 것"을 줄 목록에 어떻게 보이고 거를지.
8. **이 툴이 여는 단위** — 연출 층 폴더를 연다. 진행 JSON과 대사 층은 짝지은 `exported/`에서 읽는다 — 그 짝을 어디에 적나(`ToolSettings`?).

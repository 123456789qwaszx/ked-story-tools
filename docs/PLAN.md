앞선 일: ked-presentation-runtime `docs/PLAN_line-anchor.md`(줄의 앵커 — N1 ~ N3 끝) · `docs/PLAN_rig-layers.md`(리그의 계층 — 진행 중)

## 0. 한 문장

> **yarn 한 파일이 정본으로 남고, 명세 표 하나와 함수 둘(줄 읽기 · 줄 고치기)이 그 파일을 `LineId / 스텝 / 종류`로 읽고 고친다.**
> 연출가는 yarn을 보지 않는다. 런타임의 재생 구조는 바꾸지 않는다.

## 1. 왜

### 1.1 병목

연출 카드로 AI가 초안 연출을 내고 사람이 화면을 보며 고친다. 고치는 자리가 막힌다 — yarn에서 대사 하나에 연출 커맨드가 열 줄 넘게 엮여 있어 무엇을 고칠지 찾기 어렵다.

### 1.2 핵심 둘 (소유자)

1. **한 연출을 고칠 때 그 줄의 모든 커맨드를 볼 필요가 없다.** 연출가는 화면에서 아쉬운 곳을 찾고, 그것이 카메라인지 · 자리와 구도인지 · 모션과 연기인지 · 화면 효과인지 가른 뒤, 그 줄(프로젝트에서 유일한 LineId)의 그 종류만 걸러 본다. 더하고 바꾸고 수치를 맞추는 일도 그 한 종류로 좁힌 카탈로그를 보며 한다. 카탈로그는 **그 종류의 커맨드 어휘와 그 종류로 분류된 연출 카드** 둘을 함께 가리킨다.
2. **yarn의 복잡한 부분을 작업자에게 드러내지 않는다.** ked-story-director가 시나리오 작가에게 하는 일을 연출가에게 한다. ked-motion-tool-extend는 이 방향으로 만들었으나 범위가 너무 컸다 — 방향만 가져온다.

### 1.3 이미 서 있는 바탕

| 바탕 | 주는 것 |
|---|---|
| 리그를 나눔(캐릭터 · 카메라 · 스테이지) · 팩토리를 종류별로 나눔 | 커맨드가 무엇을 바꾸는지가 대상으로 갈린다 |
| 큰 커맨드를 걷고 작게 나눔(리그의 계층) | 커맨드 하나가 한 축을 적힌 값으로 놓는다 — 무대를 읽지 않는다 |
| 모션 툴(ked-motion-tool-characterRig) | 연기의 세부는 대본 밖(프리셋 · 커브)에 있다. 대본에는 이름 한 줄 |
| 줄의 앵커(N1 ~ N3) | 모든 커맨드가 한 줄의 한 앵커에 속한다. 주소의 앞 두 칸(LineId / 스텝)이 생겼다 |
| 되감기 때 `DialogueRunner`가 고친 `YarnProject`로 새로 시작한다 | yarn을 고치고 되감으면 화면에 반영된다 — 새 장치가 필요 없다 |

커맨드를 작게 나눈 대가가 줄 수다. 그래서 줄을 줄이는 쪽이 아니라 **필요한 만큼만 꺼내 보는 쪽**으로 간다.

### 1.4 하지 않기로 한 것 (소유자)

| | 까닭 |
|---|---|
| yarn의 줄 · 커맨드 이름을 바꾸거나 순서를 정리 | 효과가 작고 정리에도 비용이 든다 |
| yarn을 종류별 파일로 나눠 런타임이 맞춰 읽기 | 되감기가 느려지고 코드가 어려워 유지보수가 힘들었다 |
| 런타임의 타임라인(줄에 시간을 주고 절대 프레임에 앵커를 둔다) | 타자기 · 서두르기 · 트윈의 시계를 하나로 묶어야 하고, Yarn 의존을 걷는 데까지 넓어진다 |
| 줄 상자를 툴의 파일로 따로 저장하고 yarn으로 펼치기 | 줄이 앵커를 갖게 된 뒤로 상자는 yarn에서 계산된다 — 정본이 둘이 될 까닭이 없다 |

## 3. 그림

```
카드 · AI 초안 도구
      │ 한 번 낸다(D1)
      ▼
   .yarn (정본) ──────────→ 런타임(그대로) ──→ 화면을 보고 아쉬운 곳을 찾는다
      │  ▲          되감기가 고친 YarnProject로 다시 시작한다
 줄 읽기│  │줄 고치기
      ▼  │
   줄 보기: 스텝 → 종류별 커맨드 · 지연 · 간격  ←── 종류 필터 · 그 종류의 카탈로그(어휘 + 카드)
```

주소는 `LineId / 앵커 / 종류 / 순번`이다. 파일의 줄 번호는 주소가 아니다 — 고치면 밀린다. 읽을 때마다 푸는 위치로만 쓴다.

## 4. 부품

### 4.1 명세 표 — 런타임 코어 (K1)

커맨드마다 **종류 하나와 인자 칸의 목록**을 적은 표다. 지금 어휘의 정본(`Stage/Grammar/StageCommandParser.Table.cs`)은 이름마다 람다가 붙은 표라, 인자의 자리 번호와 생략값만 있고 그 인자가 무엇인지는 데이터로 없다. 툴이 `move_by s1 120u 0u 0.4s`를 슬롯 · 가로 · 세로 · 길이 · 이징의 칸으로 보여 주려면 이것이 있어야 한다.

| | |
|---|---|
| 한 줄 | 이름 · 종류 · 인자 칸(이름 · 갈래 · 생략값) |
| 인자의 갈래 | 슬롯 · 거리 · 각도 · 배율 · 길이 · 이징 · 이름(표정 · 모션 · 이모지처럼 목록에서 고른다) · 토큰(`keep_y` 같은 낱말) |
| 지키는 법 | 파서 표와 이름 · 인자 수 · 생략값이 어긋나면 EditMode 시험이 실패한다. 새 커맨드는 종류와 인자를 정하지 않고는 지나갈 수 없다 |

### 4.2 줄 읽기 — 런타임 코어 (K2)

yarn 원문과 LineId를 받아 그 줄을 돌려준다.

```
줄: "여기서 [a]2초를 채우고 표정이 바뀌고, [b]또 1초를 채우고 끄덕여."
 start   "여기서 "                       간격 2s     연기 +0s face …
 a       "2초를 채우고 표정이 바뀌고, "    간격 1s     연기 +0s face_swap …
 b       "또 1초를 채우고 끄덕여."                     연기 +0s motion …
 end
```

| 스텝마다 | 앵커 이름 · 갈래(앞 / start / 글 / end) · 대사 조각 · 간격 |
|---|---|
| 커맨드마다 | 이름 · 인자(명세 표의 칸으로) · 종류 · **앵커가 열린 뒤의 지연**(같은 앵커에서 앞선 `pause`의 합) · 파일에서의 위치 |

- 바탕은 있다 — `YarnLineGroup.Anchors` · `Body` · `LineBeatSchedule.Segment`. 더할 것은 LineId 색인 · 종류 · 지연 · 위치다.
- **`pause`는 걸러지지 않는다.** 종류로 걸러 보아도 그 커맨드가 언제 시작하는지가 남아야 한다 — `pause`는 줄로 보이지 않고 뒤 커맨드의 지연으로 보인다. 기다리는 커맨드(`screen_cover`)가 뒤를 붙잡는 것도 같은 자리에 표시한다.
- 지금 추출기(`YarnCommandTextExtractor`)는 등가성 하네스 전용이라 분기 · 선택지가 있는 파일을 다루지 않는다. 줄 읽기는 재생 순서가 필요 없다 — 대사 줄 바로 위의 `<<at>>` · `<<gap>>` 묶음만 읽으면 되므로 분기가 있어도 되게 따로 둔다.
- 쓰는 곳은 둘이다 — 툴(대본 파일에서)과 런타임의 개발 도구(재생 중, K5).

**K2에서 지은 것(2026-11-22)** — 런타임 코어 `Core/Read/`. `YarnLineReader.ReadFile(원문)`이 대사 줄마다 `LineRead`를 내고 `TryGet(LineId)`로 찾는다(`Read(원문, LineId)`는 한 줄).

| | |
|---|---|
| 줄 | LineId · 노드 · 화자 · 글 · 줄 번호 · 들여쓰기 · **묶음의 자리**(`Block` — 줄 번호와 글자 자리. 대사 줄은 들지 않는다. 묶음이 없으면 빈 범위이고 대사 줄의 머리) · 문제 |
| 스텝 | 앵커 이름 · 갈래 · 대사 조각 · 간격(과 그 줄 번호) · 기다림의 합 · 앵커의 길이(간격과 기다림의 합 가운데 큰 쪽) |
| 커맨드 | 이름 · 인자 · 명세 표의 칸(`Bound`) · 종류 · 지연 · 길이(대본의 것 — 없으면 null) · 기다리는가 · 줄 번호 · 종류 안의 순번(`KindIndex` — 주소의 마지막 칸) |
| 앵커 밖 | 바로 실행하는 명령(`Immediate`)과 Yarn의 `set` · `declare` · `call` · `wait` — `LineRead.Immediate` |

- 추출기는 넓히지 않고 따로 두었다. 분기(`if` · `jump` · `detour` …)와 선택지는 묶음을 끊고, 그 위에 남은 `at` · `gap`은 파일의 문제로 적는다.
- 표에 없는 명령은 종류 없이 싣고 줄의 문제로 적는다 — 포크의 대본은 포크의 표로 읽는다.
- 프레임 시간표는 `LineTimetable.Build(줄, 타자기, 길이를 묻는 함수)` — 앵커가 열리는 때 · 커맨드의 시작과 길이 · 넘김을 받는 때를 초와 프레임(30fps)으로 낸다. 글 표지 · `end`는 어림(`Estimated`)이다. 타자기의 속도(`TypewriterPacing`)는 프로젝트의 값이라 툴이 넣는다(예제 씬은 초당 20자).

### 4.3 줄 고치기 — 이 저장소 (K3)

런타임은 yarn을 쓰지 않는다 — 쓰는 함수는 툴의 도메인 층에 둔다.

| 조작 | yarn에 적히는 것 |
|---|---|
| 값 바꾸기 | 그 `<<at>>` 줄의 인자 |
| 커맨드 더하기 · 빼기 | 그 앵커의 `<<at>>` 줄 |
| 지연 바꾸기 | 그 커맨드 앞의 `<<at 이름 pause 길이>>`를 넣거나 고친다 |
| 간격 바꾸기 | `<<gap 이름 길이>>` |

- 고친 뒤에는 **그 줄의 커맨드 묶음만** 다시 쓴다. 파일의 다른 곳은 글자 하나 바뀌지 않는다.
- **묶음 안에서도 손대지 않은 커맨드 줄은 원문 그대로 둔다** — 줄 끝의 카드 출처 주석(P5)이 살아남아야 한다. 줄 읽기(`YarnLineReader`)는 주석을 벗기고 읽어 결과에 주석이 없으므로, 다시 쓸 때는 커맨드의 줄 번호로 원문 줄을 가져온다. 값을 바꾼 줄은 주석을 그대로 붙이고, 뺀 커맨드는 주석과 함께 사라진다.
- 쓰기 전에 원문 검사(줄의 앵커 AR6 · AR7 · AR10)를 돌린다 — 깨진 yarn은 쓰지 않는다.
- 새 표기(`<<at>>` · `<<gap>>` · 앞 앵커 표지)만 쓴다 — 옛 표기(`<<step>>` · `at` 없는 명령)의 대본은 읽기만 한다.
- 연출가는 `pause` · `gap`이라는 낱말을 보지 않는다.

**K3에서 지은 것(2026-11-22)** — `src/St.Authoring/Editing/`. `LineEditor.Apply(원문, 조작)`이 순수 함수로 고친 원문을 낸다. 쓰는 법은 [`CLI.md`](CLI.md).

| | |
|---|---|
| 조작 | `SetValue`(주소 · 칸 · 값 — null이면 비운다) · `AddCommand`(LineId · 앵커 · 이름 · 인자 · 순번) · `RemoveCommand`(주소) · `SetDelay`(주소 · 길이) · `SetGap`(LineId · 앵커 · 길이) |
| 주소 | `CommandAddress`(LineId · 앵커 · 종류 · 순번) — 글로는 `ln_abc/start/acting/0` |
| 한 조작 = 한 줄 | 조작 하나는 묶음의 물리적인 줄 하나를 고치거나(`<<…>>` 안만 — 들여쓰기 · 줄 끝 주석 · 줄바꿈은 그대로) 넣거나 뺀다. 묶음의 다른 줄도 바뀌지 않는다 |
| 쓰기 전 검사 | 고친 글을 줄 읽기로 다시 읽는다 — ① 새 문제가 생기면 ② 다른 줄의 읽기가 달라지면 ③ 읽은 값이 고친 값과 다르면 거절한다. 코어에 원문 검사 함수가 따로 없어 줄 읽기의 문제 목록(AR6 · AR7 · AR10을 적는다)을 고치기 전과 견준다. 커맨드가 남지 않은 표지만 경고로 받아들인다(AR7) |
| 지연 | 그 커맨드 바로 앞의 `pause`를 넣거나 · 고치거나 · 뺀다. 더 앞선 기다림보다 당길 수 없다. `pause`는 뒤 커맨드를 모두 붙잡으므로 **그 뒤의 커맨드도 같은 만큼 움직인다** |
| 새 줄의 자리 | 그 앵커의 마지막 커맨드 다음. 커맨드가 없는 앵커면 제 간격 줄 앞 → 뒤 앵커의 첫 줄 앞 → 묶음의 마지막 커맨드 다음. 간격은 그 앵커의 커맨드 뒤 |
| 되돌리기 | `StagingEditor` — 조작 하나가 한 칸. 같은 값 · 거절은 기록하지 않는다(`Revision`) |
| 파일 | `ScriptFile`(UTF-8만, BOM · 줄 끝 문자 그대로) · `ScriptSet`(파일 또는 폴더 — LineId로 찾는다) · `SpecTables`(포크의 `command-specs.json`) |
| 하지 않는 것 | 값의 뜻 검사(그 표정 · 슬롯이 있는가, 거리 · 배율의 꼴) — 시간 토큰과 정해진 낱말만 본다. 명세 표에 없는 커맨드는 주소가 없어 고치지 못한다 |

- 카드 — 작업공간 `catalog/cards.json`의 58장에는 `class`(몸짓 16 · 화면 10 · 등장 · 퇴장 7 · 겹친 무대 6 · 자리 · 크기 6 · 구도 5 · 표정 5 · 카메라 3)가 있다. 이 여덟을 종류 넷에 잇는 표 하나를 작업공간에 둔다 — **두었다(2026-11-22, 작업공간 `catalog/kinds.json`)**: 카메라 → 카메라 · 구도 · 등장 · 퇴장 · 자리 · 크기 → 자리와 구도 · 표정 · 몸짓 → 연기 · 화면 · 겹친 무대 → 화면(소유자). 겹친 무대의 카드에는 안에 세우는 사람의 세우기 · 자리와 구도 커맨드가 딸려 있다. 카드 하나만 다른 종류에 두는 칸(`cards`)이 있고 지금은 비어 있다. 카드를 고르면 그 카드의 커맨드 묶음이 "커맨드 더하기"로 들어간다.

| 칸 | 갈래마다 — 글 칸(Enter나 포커스가 떠날 때 고친다 · Esc는 되돌린다 · 비우면 그 칸을 적지 않는다), 정해진 낱말은 고르는 칸, 낱말 칸(`keep_y`)은 체크. 적지 않은 칸에는 생략값이 흐리게 보인다 |
| 지연 · 간격 | 시간 토큰(`15fr` · `0.5s`). 지연을 비우면 0, 간격을 비우면 걷는다. `pause` · `gap`이라는 낱말은 화면에 없다 |
| 쓰기 | **조작마다 바로 파일에 쓴다(U1).** 거절되면 쓰지 않고 까닭이 오른쪽에 뜬다 |
| 되돌리기 | 위의 단추 · Ctrl+Z / Ctrl+Y(Ctrl+Shift+Z) — 파일을 넘나드는 한 줄이고 되돌린 것도 파일에 쓴다. 글 칸 안의 Ctrl+Z는 그 칸의 것이다 |
| 바깥의 고침 | 창으로 돌아오거나 "다시 읽기"(F5)를 누르면 디스크를 다시 본다. 바깥에서 바뀐 파일은 덮어쓰지 않고 그 파일의 되돌리기를 비운다 |
| 고친 줄 | 연 뒤로 커맨드 묶음이 달라진 줄은 목록에 `● 고침`이 붙는다(되돌려 처음과 같아지면 사라진다) |
| 읽기만 | 옛 표기 줄 · LineId가 없는 줄은 칸이 잠기고 까닭이 보인다 |
| 코드 | 도메인 `St.Authoring/Editing/EditSession`(파일과 되돌리기의 살림 — 고치는 길은 `LineEditor` 그대로). 화면 `MainWindow.Edit.cs`(칸 · 조작) · `MainWindow.Line.cs`(고르기) |
| 까닭의 말 | 거절의 까닭 · 읽기만인 까닭 · 문제는 화면의 말로 바뀌어 보인다(`Views/DirectorText`) — `<<face_swap>>`은 `face_swap`으로, 칸의 열쇠(`(duration)`)는 걷힌다. 명령줄의 글은 그대로다 |

### 4.6 UX — 타임라인과 그 밖 (D7)

툴은 무대를 그리지 않는 대신(D6) 고치는 손이 빨라야 한다. 기준은 형제 툴과 마야다.

**타임라인** — 줄 하나를 가로로 편다.

```
            in ────────┐ start ──────────────┐ a ─────────┐ end
프레임       0          30                     78           96
카메라                  ▓▓▓▓▓▓▓▓ shot_zoom
자리와 구도  ▓▓▓ fade_out   ░▓▓▓ fade
연기                    ● face               ▓ face_swap   ● emoji
화면
대사                    "아, 음…… "           "이건 비밀인데."
```

| | |
|---|---|
| 가로 | 프레임. 앵커가 세로줄이고, 앵커 사이는 간격(앞 앵커)이거나 글이 쳐지는 시간(글 표지)이다 |
| 세로 | 종류의 트랙 — 종류 필터는 트랙을 접고 펴는 일이다 |
| 막대 | 길이가 있는 커맨드(트윈)는 막대, 없는 것은 점. 막대의 왼쪽 끝은 앵커가 열린 때 + 지연 |
| 끌기 | 막대를 옆으로 → 지연(`pause`) · 막대의 오른쪽 끝 → 길이 인자 · 앵커의 세로줄 → 앞 앵커의 `<<gap>>` |
| 참인 범위 | 기준 속도의 보통 재생. 글이 있는 구간은 타자기 속도로 셈한 어림이다 — 화면에 그렇게 표시한다 |
| 모르는 길이 | 모션 · 이모지 클립의 길이는 대본에 없다 — `motions.json` · `emojis.json`에서 읽는다 |

글 표지 앵커는 시각만 당길 수 없다(타자기가 그 글자에 닿아야 열린다) — 뒤로 미는 것만 `<<gap>>`으로 적힌다. 당기려면 표지의 글자 자리를 옮겨야 하고, 그것은 P4가 뺀 조작이다.

**K4-4에서 지은 것(2026-11-22).** 고른 줄의 머리 아래에 선다 — 그 아래 스텝 목록과 같은 줄을 본다.

| | |
|---|---|
| 그림 | 위에 프레임 눈금과 앵커의 이름, 켜진 종류마다 트랙(같은 트랙에서 겹치는 막대는 줄을 나눈다), 맨 아래 대사 조각. 길이를 모르는 커맨드(표정 · 이모지 · 모션 파일에 없는 모션)는 점(마름모). 글에 걸린 앵커는 점선, 넘김을 받는 때는 노란 줄. 고른 커맨드의 막대는 테를 두른다 |
| 끌기 | 막대의 몸 → 지연 · 오른쪽 끝 → 길이 칸 · 앵커의 세로줄 → 앞 앵커의 간격 · 노란 줄 → `end`의 간격. 시각은 프레임에 맞는다. **끄는 동안에는 그림만 따라오고 놓을 때 한 번 쓴다** |
| 막대 하나만(U2) | 막대를 끌면 **그 막대만** 옮긴다 — 같은 앵커에서 바로 뒤에 오는 커맨드의 지연을 되맞춘다(조작 둘 · 되돌리기 한 칸). 뒤 커맨드가 그 막대보다 앞설 수는 없어, 넘어서게 끌면 함께 밀린다. Shift를 누르고 끌면 `pause`의 뜻 그대로 뒤의 커맨드가 모두 함께 움직인다 |
| 한계가 그림에 보이는 곳 | 더 앞선 기다림보다 앞으로는 막대가 가지 않는다. 글에 걸린 앵커는 뒤로만 밀린다 — 당기면 간격이 걷힐 뿐이다(표지를 옮기는 일은 P4가 뺐다). 간격이 그 앵커의 기다림보다 짧으면 뜻이 없어 걷는다 |
| 누르기 | 막대를 누르면(끌지 않고) 그 커맨드가 골라져 오른쪽에 칸이 선다 |
| 모션의 길이 | 대본 곁의 `motions.json`(모두가 쓰는 것)과 `<대본 이름>.motions.json`(그 편의 것)에서 읽는다 — 작업공간의 꼴이다 |
| 타자기 | 초당 글자 수를 타임라인 위의 칸에 적는다(Enter) — 대본마다 기억한다(U3). 기본은 20(런타임 예제 씬). 대사창이 열리는 시간(`StartDelay`)은 0으로 둔다 |
| 읽기만 | 옛 표기 줄은 보이기만 하고 끌리지 않는다 |
| 코드 | 도메인 `Reading/LineTimeline`(코어의 `LineTimetable`에 주소 · 종류 필터) · `Reading/ClipLengths` · `Editing/TimelineEdits`(끈 것 → 조작). 화면 `Views/TimelineLayout`(자리 셈 · 잡기 — 순수 계산) · `Views/TimelineView`(그리기 · 입력) · `MainWindow.Timeline.cs` |
| 남은 것 | 이모지의 길이(점으로 보인다) · 기다리는 커맨드(`screen_cover`)가 뒤를 붙잡는 것의 표시 · 넓혔을 때 트랙의 이름이 함께 굴러가는 것 |

### 4.7 대본의 단위 — 챕터 · 장면 · 에피소드 (D8)

실제 대본 두 곳을 보았다(2026-11-22). 둘 다 대본 곁에 `*.progression.json`(ked-progression의 챕터)이 있다 — 챕터와 에피소드의 이름 · 차례는 거기서 읽는다.

| | ked-story-director가 내보낸 것(`exported/`) | 작업공간(`runtime/Assets/Workspace/Dialogue`) |
|---|---|---|
| 챕터 | `ch01.progression.json` — `ChapterId` · `DisplayName` · `Nodes` | 편마다 `ch05_02.progression.json` — 노드 하나 |
| 장면 | **yarn 파일 하나** — `yarn/<챕터>_<장면>.yarn`. 노드의 `SceneId`. 보이는 이름은 파일 머리의 주석 `// 장면: 이름 (id)` | 파일 하나가 편 하나 — `SceneId`가 편 이름 |
| 에피소드 | **yarn 노드 하나** — `title:`이 노드의 `DialogueEntryId`. 이름은 `Title`(파일에는 `// 에피소드: 이름`) | 노드 하나 |

| 표기 | — | 새 표기뿐이다 — 본 세 편(379줄)이 모두 고칠 수 있는 줄이고 줄 읽기의 문제가 0개다. 초안에는 `// card:B03`이 줄 끝에 붙어 있다 |

**지은 것(2026-11-22 — K4-1을 고쳤다): 챕터 고르기 → 장면 고르기 → 그 장면의 에피소드가 차례로 선 줄 목록.** 에피소드는 목록의 머리(이름 · 노드 · 줄 수)로 갈리고, 하나만 골라 볼 수 있다. 줄 찾기와 종류 필터는 고른 장면 안에서 건다.

- 장면의 차례는 에피소드가 진행 파일에 처음 나오는 차례다(진행 파일에는 장면의 차례가 따로 없다). 장면의 이름은 그 에피소드가 든 yarn 파일의 `// 장면: 이름 (id)`, 없으면 `SceneId`.
- 진행 파일에는 있는데 대본에 노드가 없는 에피소드는 빈 채로 서고 "대본에 이 노드가 없다"로 보인다.
- 진행 파일에 없는 yarn 노드는 맨 뒤의 챕터 하나에 모인다 — 파일이 장면, 노드가 에피소드. 진행 파일이 없는 폴더(와 파일 하나)는 그 챕터 하나로 열린다.
- 에피소드의 머리를 누르면 접히고 펴진다(K4-5). 아직 없는 것 — 챕터 · 장면을 넘나드는 찾기.

## 5. 런타임과 잇는 가닥

| 방향 | 무엇 | 수단 | 언제 |

## 6. 시간

런타임에는 타임라인이 없다(§1.4). 순서와 최소 간격으로 돈다.

| | 자리 |
|---|---|
| 같은 앵커의 뒤 커맨드를 늦춘다 | `pause`(쿠션) · 기다리는 커맨드 — 줄의 앵커 A7 · AR2 |
| 다음 스텝(대사 + 커맨드)을 늦춘다 | `<<gap>>` — A8 · AR3 |
| 넘김을 늦춘다 | `end`의 `<<gap>>` — AR4 |

프레임 시간표는 **계산해서 보여 주는 면**이다 — 앵커 · 간격 · 글 · 타자기 속도에서 나온다. 저장하지 않는다. 기준 속도의 보통 재생에서만 참이고(서두르기 · 빨리 넘기기 · 번역문에서는 달라진다), 글이 없는 앞 앵커 구간에서만 정확하다. 툴의 타임라인(§4.6)이 이 면이다 — 시간표를 내는 계산은 줄 읽기 곁에 순수 함수로 둔다.
